# ft3 2.0: the agent-only release

ft3 2.0 makes ft3 a framework whose only users are agents: coding agents
that author ft3 packages, and calling agents that consume ft3 APIs. Humans
set direction; they no longer write or call ft3 directly.

This file is the plan of record. Keep it current in the same commit as any
change it describes.

## Principles

1. **The schema is the contract.** Anything a Field declares is enforced
   where input enters the system. Anything the framework does is stated in
   the reference, not discovered.
2. **Errors are instructions.** Every ft3 error is an ordinary `Exception`
   with a stable `code` and a message that names the offending thing and the
   fix.
3. **No hidden magic.** Behavior follows from what is visible in the
   package: no frame inspection, no import-order dependence, no
   positional wiring.
4. **Cheap to import.** ft3 is deployed to serverless. Nothing runs at
   import time that scales with the size of an API. OpenAPI documents are
   build-time artifacts.
5. **Zero dependency.** Stdlib only. No MCP.
6. **Production never breaks.** Every wire-visible change ships behind a
   compatibility switch. Hydrating stored records stays lenient.

## Compatibility design

### The global switch

`FT3_LEGACY_WIRE=true` (environment, read at import) restores every 1.x
request-side and response-side wire behavior at once. A downstream API
upgrades with the switch on, reviews the WARNING log lines ft3 emits for
each legacy behavior it exercised, then migrates field by field and turns
the switch off. Non-wire fixes (exception base, `bool()`, `deepcopy`,
route anchoring) are not switchable: no working code depends on them.

### Per-Field overrides

New `Field` options, all OpenAPI-neutral. Each defaults to the 2.0
behavior, or to the 1.x behavior when the global switch is on.

| Option | 2.0 default | 1.x behavior it restores |
|---|---|---|
| `camel_case_keys` | `False`: dict values are never re-keyed | first-level dict keys camelCased on the wire |
| `drop_null_items` | `False`: list nulls keep their positions | `None` items dropped from list Fields on the wire |

### Strict and lenient parsing

Two parse modes. **Strict** enforces every declared constraint (`enum`,
`minimum`/`maximum`, `min_length`/`max_length`, `pattern`,
`min_items`/`max_items`/`unique_items`, `multiple_of`), allows only
lossless coercion (`'3'` to `3` is fine; `3.9` to an int raises; a bool in
an int Field raises), and treats `required` as "must be present".
**Lenient** is exactly 1.x hydrate behavior, so stored records keep loading;
each swallowed violation is logged at WARNING once per class and field.

| Path | Mode |
|---|---|
| Generated request parsing (body, query, path) | strict; lenient under `FT3_LEGACY_WIRE` |
| `Field.parse(value, strict=True)` | strict |
| Plain construction `Model(record)` | lenient by default; `class Model(Object, strict=True)` opts in, inherited by subclasses |

Unknown keys are dropped everywhere, with a WARNING once per class and key.
This is more tolerant than 1.x, which rejected unknown keys inside
embedded typed lists.

On generated request input, private-underscore Fields are rejected with a
400 (accepted with a one-time WARNING under the global switch), `read_only`
Fields are dropped with a one-time WARNING in both modes (round-trip `PUT`s
routinely echo them), and on `POST` and `PUT` every `required` field must
be present and non-null (400, or a one-time WARNING under the switch).

Error bodies gain an additive `errorRef` key: the ft3 exception `code`, or
the exception class name in snake_case. HTTP codes follow the exception
MRO, so subclasses inherit their parent's status.

### Explicitly unchanged in 2.0

- Routing shape: collection and item paths, no verb subpaths, state
  transitions as `PUT` with `action_*` booleans, one GET surface per
  resource.
- Object equality and hashing (hash-field identity), and `a - b` yielding
  the right-hand values.
- `to_dict()` omitting `read_only` Fields by default. Downstream persistence
  layers rely on it.
- `as_response` omitting nulls (its docstring is corrected).
- `lazy_docs=True` as the default. Doc generation never runs at import.

## Release

Work lands on the `v2` branch. A pull request to `main` publishes
`2.0.0-rc.N` prereleases; downstream projects run their full suites and
contract pins against an rc before bumping. Merging the pull request is
the 2.0.0 release. Fixes needed on 1.x ship from a maintenance branch.

## Contract tests

`src/tests/contracts/` pins every behavior ft3 guarantees to the packages
built on it. Downstream projects mirror these pins. Change one only with a
coordinated release.
